# PRD: christen-route — route headless launches through the wrapper

**Status:** Draft v0.1
**build_target:** mixed
**build_into:** `~/wintermute/christen`
**Vision:** visions/christen.md

## TL;DR

The reason every session is born with id `0…0` is that no launch site routes
through `agentns-claude`. **christen-route** closes that gap for the
deterministic sites — the systemd user units — by generating drop-in files
that rewrite each `ExecStart` to `agentns-claude --intent <derived> --budget
<default> -- <original>`. It defaults to **print-only**; `--apply` writes the
drop-ins under `~/.config/systemd/user/<unit>.d/` but **never** runs
`daemon-reload`, `enable`, or `restart` — it prints those lines for the user.
For the interactive shell site it can only `Advise` (print an alias). This is
the load-bearing wire the whole substrate has been waiting on.

## Why this exists

- **The sites are concrete and editable, measured 2026-06-05.**
  `~/.config/systemd/user/claude-build.service` →
  `ExecStart=/home/jsy/.local/bin/claude-build-headless.sh`;
  `claude-dream.service` and `claude-self-review.service` are the same
  shape. These three are headless, deterministic, and exactly where intent
  tags + kernel budgets matter most (a runaway `/build` is the canonical
  reason budget enforcement exists — cf. `self_build_jam_leaked_tracer`,
  `self_build_detached_cgroup_teardown`).
- **The wrapper is ready and waiting.** `~/.local/bin/agentns-claude
  --intent <tag> [--budget <spec>] -- <cmd>` exists; `agorabus-session-start.sh:51`
  already reads `/proc/self/agent_session` expecting the real id this routing
  produces.
- **A hook cannot do this.** The SessionStart hook runs inside an
  already-spawned `claude`; `unshare(CLONE_NEWAGENT)` there affects only the
  hook process and is lost on its exit. The wrap must happen at **exec
  time**, which means editing the unit that does the exec — what this PRD
  generates.
- **Auto-editing user state is forbidden by policy.** `feedback_classifier_per_command`
  and the dream/build install convention: installers PRINT the change and
  the enable lines; they do not auto-edit `~/.claude`/systemd or auto-enable
  timers. christen-route obeys this — `--apply` writes only the drop-in
  files, and prints (never runs) `systemctl --user daemon-reload` + restart.
- Depends on christen-plan (the `RoutePlan` + `SystemdSource` contract).

## What this builds

Extend the `christen` crate (bump minor) with the real `SystemdSource`, a
drop-in renderer, and a `christen route` subcommand.

**`SystemdSource`** (impl of christen-plan's `LaunchSiteSource`) — discovers
sites by scanning `ChristenConfig.systemd_dir` for `*.service` whose
`ExecStart` references a `claude-*-headless.sh` (or `claude` directly), plus
a synthetic `ShellRc` site for the interactive launch. Pure scan → `RawSite`s;
the `plan` from christen-plan does the classification.

**The drop-in renderer** — a pure
`render_dropin(unit, exec_start, intent, budget) -> DropIn` where `DropIn {
path: PathBuf, contents: String }` and `contents` is the canonical override:

```ini
# Generated by christen route — routes this session through the agent namespace.
[Service]
ExecStart=
ExecStart=/home/jsy/.local/bin/agentns-claude --intent /build --budget wall=7200s,fork=2000 -- /home/jsy/.local/bin/claude-build-headless.sh
```

(The empty `ExecStart=` is required to clear the original before re-setting —
a systemd correctness detail the renderer must emit and a test must assert.)
The renderer makes **zero** filesystem calls; it returns the `DropIn` value.

**The `christen route` subcommand:**

- default (`christen route`) — print the `RoutePlan` and, for each `Wire`,
  the drop-in path + full contents it *would* write; print the `Advise`
  snippet for the shell site; print nothing to disk.
- `--apply` — write each `Wire`'s drop-in to
  `~/.config/systemd/user/<unit>.d/10-christen.conf` (create the `.d` dir),
  then **print** (never run): the `systemctl --user daemon-reload` and
  per-unit restart lines, and a reminder that `agentns-claude` needs the
  `cap_sys_admin` file cap (`christen cap`) or the unshare will EPERM and
  fall back to an unwrapped exec.
- `--unit <name>` — restrict to one unit (idempotent: re-applying writes
  identical contents).

**Offline gate:** every generated drop-in must pass `systemd-analyze --user
verify` (run against a temp unit + drop-in in a test) — this is the
correctness gate that substitutes for not being able to enable the units on
the build box.

## Acceptance criteria

1. `cargo build` + `cargo test` pass offline. `render_dropin` is pure (no
   filesystem calls — asserted) and emits the clear-then-set `ExecStart=` /
   `ExecStart=…` pair; a test asserts both lines are present and ordered.
2. `SystemdSource` parses a fixture unit directory into `RawSite`s with the
   correct `exec_line`; a `claude-build.service` fixture yields a site whose
   derived intent is `/build` and whose `Wire.to` wraps the original
   `ExecStart` in `agentns-claude --intent /build --budget <cfg-default> --`.
3. `christen route` (no flag) prints the plan + every drop-in's path and
   contents and writes **nothing** to disk (a test runs it against a temp
   `systemd_dir` and asserts the `.d` dirs do not appear).
4. `christen route --apply` writes `10-christen.conf` under each unit's `.d`
   directory with the rendered contents, and **prints** (does not execute)
   the `daemon-reload` + restart lines and the `christen cap` reminder;
   re-running `--apply` is idempotent (identical bytes).
5. A generated drop-in passes `systemd-analyze --user verify` against a temp
   base unit + the drop-in; covered by an integration test (skipped with a
   logged note if `systemd-analyze` is absent, never silently passed —
   `self_orphaned_mock_tests` discipline).
6. The interactive `ShellRc` site yields an `Advise` action whose snippet is
   a copy-pasteable alias (`alias claude='agentns-claude --intent interactive
   -- claude'`); printed, never written.
7. **Live wiring on the real laptop units** (write drop-ins for the three
   real `claude-*.service`, reload, confirm a subsequent headless tick reads
   a nonzero `agent_session`) — **deferred_acs:[7]** (the cloud box has no
   real units, no `-wintermute` kernel, no session history; needs the user
   to reload + the cap from christen-cap).
8. README documents the drop-in format, the print-vs-apply boundary, the
   "never enable/restart" rule, the `systemd-analyze verify` gate, and the
   `christen cap` prerequisite.
