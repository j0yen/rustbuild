## TL;DR

Knowing a primitive is dark is half the job; the other half is the *exact*
command that revives it. Today that command lives in the self-review journal as
prose a human has to find and retype. `quicken-remedy` extends the `quicken`
workspace so every non-live verdict carries the precise remediation, with a
strict safety posture: print-only by default, auto-apply only the safe userspace
subset (group/udev), never a kernel install or `sudo` step without explicit
opt-in.

## Why this exists

- **Evidence — the fix already exists and is being retyped by hand.** The
  2026-06-03 self-review journal spells out the memlog remediation verbatim:
  `sudo pacman -U …linux-wintermute-7.0.10.arch1-10…pkg.tar.zst` then reboot, or
  the no-reboot path `sudo systemd-sysusers …memlog.conf && sudo udevadm trigger
  /dev/memlog && newgrp memlog`. That command is regenerated by a human every
  review. It should be emitted by `quicken-remedy` from the probe's evidence.
- **Evidence — the safe subset is genuinely safe.** Of the dark primitives, only
  the userspace group/udev step (`newgrp`, `udevadm trigger`) is safe to
  auto-apply; the `pacman -U` of a user-protected kernel pkg needs a reboot and a
  human (memory `feedback_classifier_per_command`, and pacman-protected is
  flagged "user-only" every review). The tool must distinguish these tiers.
- **Why mirror `rollout`'s posture:** the `vigil` vision established that a tool
  whose action half mutates real state defaults to `--dry-run` and acts
  one-careful-step-at-a-time. `quicken-remedy` adopts the same default-print,
  opt-in-apply ethos.

## What this builds

- A `quicken-remedy` lib module + `quicken remedy` subcommand (extends the
  existing binary; consumes `quicken-probe`'s `PrimitiveReport`).
- A `Remediation` type: `{ primitive, steps: Vec<RemedyStep> }` where each
  `RemedyStep` carries `{ command: String, tier: Tier, requires_reboot: bool,
  rationale: String }` and `Tier` is `SafeUserspace | RequiresSudo |
  RequiresReboot | ReportOnly` (e.g. agentns all-zeros is kernel-side →
  `ReportOnly` with an honest "no userspace fix" note).
- A `remediation_for(report: &PrimitiveReport) -> Option<Remediation>` mapping,
  derived deterministically from the verdict + evidence (e.g. memlog
  `StagedNotInstalled` → a `RequiresReboot` `pacman -U <highest-pkgrel-path>`
  step **plus** a `SafeUserspace` no-reboot sysusers/udev/newgrp alternative,
  using the pkgrel + pkg-dir path recorded in the evidence).
- **CLI**:
  - `quicken remedy` (default `--dry-run`/`--print`): prints, per dark
    primitive, the ordered steps tagged by tier; never executes anything.
  - `quicken remedy --apply`: executes **only** `SafeUserspace` steps; prints
    (does not run) every `RequiresSudo`/`RequiresReboot`/`ReportOnly` step and
    says so. Re-probes the affected primitive afterward and reports the new
    verdict.
  - `quicken remedy --json`: machine-readable `Vec<Remediation>`.

## Acceptance criteria

1. `quicken remedy --help` documents `--apply`, `--dry-run`/`--print` (default),
   and `--json`.
2. For a fixture memlog `StagedNotInstalled` report, `remediation_for` returns
   both a `RequiresReboot` `pacman -U` step whose path contains the
   highest-pkgrel pkg filename from the evidence **and** a `SafeUserspace`
   no-reboot alternative (sysusers/udev/newgrp) — asserted as exact strings.
3. For a fixture agentns `Inert` report, the remediation tier is `ReportOnly`
   with a rationale string stating there is no userspace fix (no command that
   claims to revive it).
4. `quicken remedy` (default) executes nothing — a test wraps the step executor
   with a recording fake and asserts **zero** commands ran in dry-run mode.
5. `quicken remedy --apply` runs **only** `SafeUserspace` steps and skips all
   other tiers — asserted via the recording fake on a fixture with mixed tiers
   (the `pacman -U` step must NOT be among the executed commands).
6. `--json` output round-trips into `Vec<Remediation>`.
7. Tests use injected fixtures + a recording command executor; **no real command
   is run, no network, no writes outside the test tmpdir** (cloud-build-safe).
8. (Manual, live-only) `quicken remedy --apply` on the real laptop revives the
   memlog group membership via the safe userspace path and a follow-up
   `quicken probe` reports memlog `Live` — verified by hand, since the cloud box
   has no `/dev/memlog`.
