# PRD: rosetta-prov — ethical decisions as W3C PROV-O linked data

Status: Draft v0.1
build_target: rust-cli
Vision: visions/rosetta.md

## TL;DR

`ousia-guard` produces a rich ethical verdict — `Evaluation { verdict,
rules_fired, justifications }` (gate.rs:51) with an axiom-chain justification —
and then it dies as a Rust struct or a one-shot JSON blob. The *why* of an
ethical decision is never serialized in a form another tool can query, join, or
audit. `rosetta-prov` translates a guard verdict, the action it judged, and the
kernel/ledger provenance around it into a **W3C PROV-O graph** (Turtle +
JSON-LD), so "why was this action allowed/denied, by what, over which ontology,
in which session" becomes queryable linked data.

## Why this exists

Phase-1 live inspection (2026-06-15):

- `ousia-guard/src/gate.rs:51` returns `Evaluation { verdict, rules_fired,
  justifications: Vec<RuleFiring> }`; each `RuleFiring` carries `rule_id`,
  `subject`, and a `justification: Vec<String>` axiom chain (gate.rs:57-64).
  This is exactly a provenance derivation — and it is thrown away after the
  CLI prints it.
- `provenance-mcp` already reads kernel-stamped `user.prov.session` /
  `user.prov.ts` xattrs; `answerable` already records a JSONL line per
  consequential action with a session id. Both describe the *who/when* of an
  action but live in formats that cannot be joined to the guard's *why*.
- The ecosystem already standardizes on `oxrdf` / `oxrdfio` / `oxigraph 0.4`
  (see `lattice-join`, `ousia-sparql` Cargo.toml) — the RDF plumbing is present;
  nothing yet emits PROV-O with it.
- `grep` over every PRD + vision: zero existing PROV-O coverage. Unclaimed.

PROV-O is the natural, standard, *already-designed* vocabulary for "this entity
was generated by this activity using these inputs and associated with this
agent." An ethical decision is precisely a provenance record.

## What this builds

New repo `~/wintermute/rosetta-prov/` (rust-cli, edition 2021, MSRV 1.85).

**Deps:** `oxrdf` (>=0.2,<0.3), `oxrdfio` (>=0.1,<0.2) — match the versions
already locked in `ousia-sparql`/`lattice-join`; `serde` + `serde_json` for
reading the guard verdict and emitting JSON-LD; `clap` v4.

**Input contract** — a JSON document (stdin or `--verdict <file>`) shaped like
`ousia-guard`'s output, with an action-context envelope:

```json
{
  "action": { "iri": "urn:wo:action:abc", "label": "deny patient X care",
              "agent_session": "<128-bit agentns id or provfs user.prov.session>" },
  "ontology": { "iri": "urn:wo:ontology", "version": "1.0.0" },
  "evaluation": { "verdict": "deny",
                  "rules_fired": ["dignity-floor"],
                  "justifications": [
                    { "rule": "dignity-floor", "subject": "wo:PatientX",
                      "justification": ["wo:PatientX a wo:SentientBeing",
                                        "SentientBeing SubClassOf bears Dignity"] } ] }
}
```

**PROV-O mapping (the core):**

- the guard check → `prov:Activity` (`rosetta:GuardCheck`), with
  `prov:startedAtTime` / `prov:endedAtTime`.
- the verdict → `prov:Entity` (`rosetta:Verdict`) `prov:wasGeneratedBy` the
  activity; `rosetta:hasVerdict "deny"`.
- the action under judgement → `prov:Entity` the activity `prov:used`.
- the ontology version → `prov:Entity` (`prov:wasInfluencedBy` /
  `prov:used`), tagged `pav:version`.
- the agent session → `prov:Agent` (`rosetta:AgentSession`) the activity
  `prov:wasAssociatedWith`; carries the provfs/agentns 128-bit id.
- each `RuleFiring` → a `prov:Entity` `prov:wasDerivedFrom` the action,
  `rosetta:firedRule <rule-iri>`, with the axiom chain as `rosetta:axiom`
  literals (one per line) so the derivation is inspectable.

**CLI:**

```
rosetta-prov emit   --verdict v.json [--format turtle|jsonld]   # → PROV-O graph
rosetta-prov emit   --verdict v.json --base http://example/      # IRI base
rosetta-prov schema                                              # print the PROV-O vocabulary/prefixes used
```

`emit` reads the verdict JSON, builds the graph in `oxrdf`, and serializes via
`oxrdfio` to Turtle (default) or JSON-LD on stdout. No network, no mutation, no
state — pure translation.

## Acceptance criteria

1. `rosetta-prov emit --verdict <fixture> --format turtle` emits valid Turtle
   that round-trips through `oxrdfio` parse without error.
2. The emitted graph contains a `prov:Activity` for the guard check, a
   `prov:Entity` verdict with `prov:wasGeneratedBy` linking to it, and a
   `prov:Agent` linked by `prov:wasAssociatedWith`.
3. The verdict literal (`allow|flag|deny`) from the input appears on the
   verdict entity, and every `rules_fired` id appears as a derived rule entity.
4. Each input `justification` axiom-chain line appears verbatim as a
   `rosetta:axiom` literal on the corresponding rule-firing entity.
5. `--format jsonld` emits JSON that parses as valid JSON **and** re-parses
   through `oxrdfio` JSON-LD back to an isomorphic graph (same triple count).
6. `agent_session` from the input appears as the `prov:Agent` identifier; when
   absent, the tool emits a blank-node agent and exits 0 (does not fail).
7. `rosetta-prov schema` prints the prefix table (prov, prov-o terms, rosetta,
   pav) used by `emit`, and exits 0.
8. A malformed verdict JSON (missing `evaluation`) exits non-zero with a
   diagnostic naming the missing field; no partial graph is written.
