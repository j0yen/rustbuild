# PRD: chaff-cron — scheduled hygiene + honest self-review line

Status: Draft v0.1
build_target: shell
build_into: /home/jsy/wintermute/chaff
Vision: visions/chaff.md

## TL;DR

chaff-survey/policy/repair/guard make the fleet's git hygiene fixable on
demand; chaff-cron makes it *stay* fixed without a human in the loop. It is
a systemd-user timer (6-hourly, mirroring adopt-cron / ballast-pilot /
consign-cron) that runs the survey + a guarded repair, and an additive
self-review skill-doc block that replaces the noisy, mostly-fake "N dirty
repos" line with an honest "N repos tracking build junk (M files)" — both
degrading to an exit-0 one-liner when chaff is absent.

## Why this exists

Live evidence (2026-06-18):

- The self-review journal reports "56 dirty repos, 8 unpushed — normal
  /build churn" every day (journals 2026-06-12..18: 37, 45, 65, 56...).
  Much of that count is tracked build junk (careen-ledger alone is 1942
  files), so the line is misleading: it reads as "work pending" when it is
  mostly chaff. self-review has no way to tell them apart today.
- The fleet is continuously regenerated by /build every 5 minutes; without
  a recurring pass, chaff-repair's one-time cleanup decays as new repos are
  scaffolded and new artifacts modified. A timer keeps it converged.
- The pattern is proven: `adopt-cron`, `ballast-pilot`, and `consign-cron`
  all install a systemd-user timer + a guarded, additive self-review block.
  chaff-cron reuses the exact shape so the laptop's scheduled-maintenance
  surface stays uniform.
- The self-review skill explicitly degrades unknown tools to a one-liner +
  exit 0 (per the "WRAP don't replace" convention in the trim/consign
  gossip notes). chaff-cron must follow that so a missing `chaff` binary
  never breaks a review.

## What this builds

Shell + unit files under `~/wintermute/chaff/contrib/`, installed into the
user systemd dir and the self-review skill.

- `contrib/chaff-cron.sh` — runs `chaff survey --format json`, logs the
  summary, then runs `chaff repair` in **dry-run by default** (so the
  scheduled pass reports but does not mutate unless a sentinel
  `~/.config/chaff/auto-repair` exists, mirroring the conservative default
  of consign-cron). Appends a one-line gossip-style note to its own log;
  emits an agorabus `chaff.report` event with `{repos, files}` if agorabus
  is reachable (fail-open if not).
- `contrib/claude-chaff.service` + `claude-chaff.timer` — `OnCalendar`
  every 6h (offset from the other maintenance timers to avoid a thundering
  herd), `Restart` not needed (oneshot). Installed via a documented
  `systemctl --user enable --now` step in the repo README.
- A self-review skill-doc block (additive, anchor-delimited) under the
  appropriate `~/.claude/skills/self-review/` phase that runs `chaff survey
  --format json` and prints `N repos tracking build junk (M files; B MiB
  in index)` IN PLACE of contributing those files to the raw "dirty repos"
  count. It WRAPS, never replaces, the existing line; if `chaff` is not on
  PATH it prints `chaff: not installed` and exits 0.

Deps: POSIX sh, `jq`, `systemctl --user`. No network beyond the optional
agorabus emit. Reuse the env conventions from adopt-cron/consign-cron.
Honor self_build_detached_cgroup_teardown if the cron ever launches a long
job (it should not — survey+dry-run repair is fast).

## Acceptance criteria

1. `contrib/chaff-cron.sh` runs `chaff survey` and writes a summary line to
   its log; with no `~/.config/chaff/auto-repair` sentinel it runs
   `chaff repair` in dry-run only (mutates nothing).
2. With the `auto-repair` sentinel present, the cron script runs
   `chaff repair --no-dry-run`.
3. `claude-chaff.timer` is a valid unit (`systemd-analyze verify` passes)
   with an `OnCalendar` of every 6h offset from adopt/ballast/consign
   timers.
4. The cron script emits an agorabus `chaff.report` event when agorabus is
   reachable and exits 0 (fail-open) when it is not.
5. The self-review block prints `N repos tracking build junk (M files…)`
   when `chaff` is installed and `chaff: not installed` + exit 0 when it is
   not.
6. The self-review block is additive and anchor-delimited; installing it
   twice does not duplicate it (idempotent).
7. The cron script's exit code is 0 on a successful survey even when repair
   is a no-op (nothing eligible).
8. `README` documents the `systemctl --user enable --now claude-chaff.timer`
   install step and the `~/.config/chaff/auto-repair` opt-in for autonomous
   repair.
